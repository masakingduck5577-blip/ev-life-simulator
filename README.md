# EV Life Simulator

萌芽（Houga）本田技術研究所テーマ／EVシミュレーター

EVを買う前に「買った後の暮らしとお金」をイメージするためのアプリです。

- **コスト比較（主役）**：EVと、ガソリン車またはハイブリッド車（HV）の総保有コストを比較。「補助金で安く買える」「燃料代が安い」の2本の柱で表示
- **今日の走り**：レンタカー返却時に、走った距離と電池の残量から本人の電費を出して、コスト比較に使う
- **相談メモ**：試算の結果と聞きたいことを1枚にまとめ、販売店のスタッフに見せる。QRコード・リンクで同じ結果をスタッフのPCで開ける。印刷・PDF保存もできる
- **A ライフスタイル**：当てはまる場面を選ぶと、合うEVの使い方を提案カードで表示
- **C 生活圏・おでかけ**：地図で行ける範囲と充電施設を確認
  - 生活圏モード：自宅・職場・よく行く場所の周りと経路の施設、季節ごとの行ける判定、年間走行距離の推定
  - 旅行モード：目的地までの航続距離、推奨充電地点、目的地の充電施設、充電費用の概算
- レンタカーの予約は準備中（画面遷移のみ）

### 使う流れ

- 点検・車検の待ち時間：ホーム →「コストを比べる」→ 相談メモ（約3分）
- レンタカー返却時：ホーム →「レンタカーを返却した方」→ 今日の走り → コスト比較 → 相談メモ
- マップとライフスタイルは、見たい人だけ（コスト比較の「暮らし・おでかけも見る」から）
- PC（幅960px以上）では、コスト比較・相談メモ・診断結果を横に広げて表示（商談用）

## 動かし方

ビルドは不要です。

- 手元で試す：`index.html` をブラウザで開く
- 公開する：このフォルダをGitHubのリポジトリに置き、Settings → Pages で `main` ブランチの `/ (root)` を公開

地図・場所検索・経路はインターネット上のサービスを使うので、オンラインで開いてください。経路サーバーにつながらないときは、直線距離×1.3の推定で計算を続けます（画面に「推定」と表示）。

## 提案カードの追加

`scenes.js` の `SCENE_CARDS` に1件足すと、選んだ場面に合わせて自動で表示されます。書き方はファイル冒頭のコメントにあります。

- 合う場面は `tags` に書く（場面に合うと2点、気になることに合うと1点、人数に合うと1点。点数の高い順に上位5枚を表示）
- 質問の選択肢を増やすときは `SCENE_TAGS` に1行足す（質問画面に自動で出る）
- 数字の裏付けは `metric` で種類を選ぶと、コスト比較の電費・電気代の設定から自動で計算されます
- 内容を確認中のカードは `draft:true` にしておくと「内容は仮です」と表示されます

## 施設データの登録

`facilities.js` の `window.FACILITIES` に1件ずつ追加します。書き方はファイル冒頭のコメントにあります。

```js
{ id:"q-yuinomori-001", name:"Honda Cars 栃木中央 ゆいの杜店", lat:36.572, lng:139.980,
  type:"quick", kw:50, ports:1, priceText:"30分 ◯円", hours:"9:00-19:00", updatedAt:"2026-10-20" },
```

- `type` は `quick`（急速）/ `normal`（普通）/ `merit`（EVで得する施設・サービス）
- 緯度経度は、Googleマップで地点を右クリックすると表示される値をそのまま使えます
- `price`（円/kWh換算）を入れると、その施設の料金で費用を計算します
- 高速道路のSA/PAには `highway:true` を付けてください
- 今入っている `【デモ】` の施設は動作確認用の架空データです。実データを入れたら削除してください（残っている間は画面に「デモ」と表示されます）
- データを集めた範囲に合わせて `window.COVERAGE` を書き換えてください。この範囲の外を通る経路には「データ対象外の区間があります」と表示します

## データの自動更新（GitHub Actions）

`.github/workflows/update-data.yml` が、GitHub上で自動で動きます。

| 対象 | いつ | 何をするか | 書き換えるファイル |
|---|---|---|---|
| 国のCEV補助金 | 毎日 6:00 | 次世代自動車振興センターのページ・お知らせ・車種ごとの金額の表を読み、受付の状況、受付終了の見込み、Honda車の金額を確かめる | `subsidy.js` |
| EV充電施設 | 毎週月曜 6:30 | OpenStreetMap から栃木県内の充電施設をすべて取り直し、Honda Charge と Honda販売店の充電器を見分ける | `chargers.js`、`chargers.csv` |

- 変わったら自動でコミットし、公開サイトにも反映されます
- 補助金の情報が変わったときと、読み取れなかったときは **Issue** で知らせます（リポジトリを Watch していればメールが届きます）
- すぐに動かすときは、Actions タブ →「データの自動更新」→「Run workflow」
- 補助金の受付が終了したと読み取れたら、アプリは補助金を0円として計算し、「受付終了」と表示します
- 読み取れなかった項目は前回の値のままです。Issueの内容を見て、必要なら `cars.js` を手で直してください
- GitHubの仕様で、リポジトリに60日間更新がないと、自動実行が止まります。止まったら Actions タブから有効にし直してください

### 初めて使うとき

1. Settings → Actions → General の「Workflow permissions」を **Read and write permissions** にして保存
2. Actions タブ →「データの自動更新」→「Run workflow」（更新するもの：all）で1回動かす
3. 数分後、`chargers.js` に充電施設が入り、アプリのデモ施設が実データに置き換わる

## 充電施設のデータ

- **自動（chargers.js）**：OpenStreetMap（誰でも編集できる公開地図データ、ODbL）から取り込みます。対象の県は `update_chargers.py` の `PREFECTURES` で増やせます（旅行先の福島・茨城・群馬など）
- **Honda Charge**：名前・運営者・ネットワークに「Honda Charge」とある施設を、赤い「H」のピンで表示します。ただし、Honda Charge の設置場所はHondaの公式アプリでしか公開されておらず、OpenStreetMap に登録されていない場所は自動では取れません。アプリで見つけた場所は `facilities.js` に `network:"Honda Charge"` を付けて追加してください（同じ場所の自動データより優先して表示します）
- **Honda販売店**：名前などに「Honda Cars」「ホンダカーズ」とある充電器
- アプリの「充電施設の一覧」（マップ → 充電施設の一覧）で、Honda Charge・販売店・急速・普通で絞り込み、自宅（未登録なら ゆいの杜店）から近い順に見られます
- 施設の詳細画面の「間違いを直す」から、OpenStreetMap のデータを直せます（直した内容は翌週の取り込みで反映）

## 補助金の金額と受付期限を手で直す

自動で読み取れなかったときや、アプリの初期値を変えるときは `cars.js` を書き換えます。`subsidy.js` に値があれば、そちらが優先されます。

- **受付終了の見込み**：`SUBSIDY` の `endText`、`endFrom`・`endTo`、`noticeDate`
- **車種ごとの金額**：`EVS` の `sub` と `SUBSIDY.amountAsOf`
- 2026年10月17日時点：受付終了の見込みは2026年12月上旬〜下旬（9月4日発表）。N-ONE e:・N-VAN e: は58万円、Super-ONE・INSIGHT は130万円（10月13日時点の表）

## 市町の補助金を更新する

`local-subsidy.js` に、栃木県内の市町ごとの EV 購入補助（金額・受付状況・いつまで・条件・ページのURL）を入れています。結果画面の「お住まいの市町」で選ぶと表示され、受付中（open・soon）のときだけ計算に入ります。市町の補助は年度の途中で予算がなくなって終わることが多いので、`status` と `until` をこまめに直してください（2026年10月18日に各市町のページで確認）。

## 相談メモの「聞きたいこと」を増やす

`memo.js` の `MEMO_ASKS` に1行足します。`auto` に条件を書くと、試算の結果に合わせて最初からチェックされます。

## 今日の走りの計算

- 使った電気 =（貸し出し時の残量% − 返却時の残量%）× 電池の容量
- 電費 = 使った電気 ÷ 走った距離。季節の係数で春・秋の条件に直してからコスト比較に使う
- 20km未満、または電費が 50〜400Wh/km の範囲を外れるときは、コスト比較に使わない（カタログ値のまま）
- コスト比較に使うのは、今日乗った車種をEVに選んでいるときだけ

## リンクとQRコード

相談メモのリンクには、試算の条件（車種・距離・単価など）と選んだ「聞きたいこと」だけを入れています。自宅の位置などマップの入力は入れず、生活圏・旅行・ライフスタイルは結果の一文だけを送ります。QRコードは qrcodejs（cdnjs）で作り、読み込めないときはQRなしで表示します。

## 計算の前提（仮置きの値）

- **ランニングコスト（月平均）** = 燃料・電気代（夏冬の電費の変化を含む1年分）＋ 自動車税・重量税 ＋ メンテナンス・車検 ＋ 保険 を12で割ったもの。メンテナンス（比べる車 年4万円・EV 年2.5万円）と保険（どちらも年6万円）は公的な平均がないため目安の値。結果画面の「単価・係数の設定」で変えられる
- **流れ**：EVを選ぶ → 使い方を入れる（1年に走る距離・ガソリン車の燃費・ガソリン代）→ 結果
- 比べるガソリン車は選ばせず、EVごとに cars.js の `rival` で決めた「同じクラスのガソリン車」と比べる（N-ONE e:→N-ONE、Super-ONE→フィット（ガソリン）、INSIGHT→ZR-V（ガソリン）、N-VAN e:→N-VAN）。燃費の初期値はその車のカタログ値（仮）
- 自宅で充電できるか（初期値：できる・80%を自宅で）は「単価・係数の設定」で変える
- EVを選ぶ画面には価格を出さず、乗車人数・大きさ・向いている使い方・満充電で走れる距離（WLTC、メーカー発表）を出す

画面の「単価・係数の設定」で変えられます。ディーラーへのヒアリングで更新予定です。

- 季節係数：春秋1.0、夏0.9、冬0.7／実電費はカタログの0.9倍
- 安心ライン（これより減らさない残量）：初期値20%
- 急速充電は80%まで。行きの最後の充電は、目的地で充電できるなら「着くのに必要な分だけ」、できないなら帰りに備えて80%まで
- 急速充電の時間：入れる量 ÷（出力 × 0.85）
- 目的地で充電できると入力され、施設データがない場合は普通充電6kWを想定
- 寄り道の距離：経路からの直線距離 × 1.3 × 往復
- 標高差は考えていません（日光・那須など上り坂の行き先は、実際は行きの消費が増えます）

## イラスト・写真

- 画面のイラストは **Microsoft Fluent Emoji（3D）**（© Microsoft Corporation、MITライセンス、https://github.com/microsoft/fluentui-emoji）を使っています。`images.js` にまとめて入れているので、フォルダは増えません
- 新しいイラストを足すときは、同じ素材から選んで `images.js` に追加します（名前で `pic("car", 48)` のように呼び出す）
- 実際の車の写真を使うときは、`cars.js` の車種に `photo:"n-one-e.jpg"` を足し、写真ファイルを同じ場所に置きます。写真があればイラストの代わりに表示します
- Hondaの公式サイトの写真は、許可なく使わないでください

## 外部サービスの利用について

- **地図**：OpenStreetMap のタイル。画面右下の著作権表示は消さないでください
- **場所の検索**：Nominatim。1秒に1回までという利用規約があるため、検索ボタンを押したときだけ呼び出しています
- **経路**：OSRM のデモサーバー

いずれも無料の公開サーバーで、デモ・試作の範囲での利用を想定しています。ディーラーで本格的に使う段階になったら、自前のサーバーや有料サービスへの切り替えが必要です（`geo.js` の `GEO_CONFIG` のURLを変えるだけで切り替えられます）。

検索した地名と、経路計算の地点はこれらのサービスに送信されます。自宅は約100m単位に丸めてから扱い、入力内容はどこにも保存しません（ページを閉じると消えます）。
